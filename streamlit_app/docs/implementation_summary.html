Implementation Summary

Proposal Generator — Streamlit frontend for the existing proposal-ai-backend FastAPI service

Overview

This adds a full Streamlit frontend (streamlit_app/) on top of the existing FastAPI backend without modifying any working backend logic. The only backend change is additive: a new GET /proposals list endpoint, needed because the backend previously only supported fetching a single proposal by id — nothing else in the backend was touched. Every other workflow step (upload, generation, review/refine) calls real, existing backend endpoints.

Before vs After

BeforeAfter

Requirement document response parsed_data stored on the model but never returned to callers Exposed as parsed_requirements on RequirementDocumentResponse, driving the Review page's Requirements Covered / Missing Information sections

Future enhancements

  • Wire Export to real backend endpoints once docx/pdf/ppt rendering and email-send exist.
  • Multi-document RFP intake — today's backend model is one file per proposal (1:1 Proposal.requirement_document_id); consolidating several source documents into one proposal would need backend pipeline changes, not just a frontend change.
  • Move SSE consumption off the main script thread (background thread + queue) so a page reconnect mid-generation doesn't require re-running the whole stream.
  • Role-based UI (the backend already has org_admin/member roles via UserRole) — e.g. hide admin-only actions for member users.
